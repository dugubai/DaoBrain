# 红绿区规则与模拟安全边界

GREEN代表可信公开样本，RED代表仅本地计算的合成内部样本，UNKNOWN代表未分类内容。区标签本身不是权限。来源字段缺失默认为UNKNOWN，不能靠客户端改标、伪造source_id或gate_approved将内容变成公开资料。

## 公开派发

gateway需要API_KEY，内部业务接口需要INTERNAL_API_KEY。gateway覆盖客户端user_id和gate_approved，并对明确公开样本话题执行服务端分类；敏感提示和未知话题不会派发公开检索。分类是严格小样本演示，不是成熟的数据防泄漏系统。

external_model需要服务端HMAC批准凭证，该凭证绑定任务ID、问题和完整证据，短期有效。服务同时核对证据来源区和可信目录中的全部字段，包括版本与hash。仅允许公开可信证据做stub摘录；真实外部API尚未接入，live模式明确返回503且不记作实际出网。

## 本地与门禁

绿区检索无命中则拒答，不查红区兜底。RED只进入本地⑧→⑪→⑨的合成样本链路。⑨始终拒绝没有独立人工复核的红区释放，返回给应用的答案和出处均为空；没有“自动脱敏后就视为公开”的捷径。

Compose的红区服务只加入internal红区网络，不发布端口或直接接入绿区；本地模型在internal本地网络，公开业务在internal绿区网络。gateway和hybrid_iface为开发跨模块调用加入多个网络，因此仍是具有桥接能力的模拟部署。模型预下载容器不接业务网络，只与模型卷和独立下载网络相连。实际网络出网阻断尚需开发机Docker验收。

## 输出及审计

候选的可信来源、区标签、字面证据与合规规则通过后才可返回。REVISE和REJECT都不能携带候选答案或出处交给用户。审计事件只记录模块、事件、任务哈希、区和受限计量字段，正文、密钥、原始错误URL和红区原文不落日志。

生产仍需独立账号及审核身份、最小权限服务凭证、受保护审批记录、独立镜像和数据卷、真正隔离网络、持久化审计及独立安全验收。共享开发密钥、内存状态和合成种子无法证明上述能力。不要将真实红区资料或病历放入此仓库、镜像或Git。
